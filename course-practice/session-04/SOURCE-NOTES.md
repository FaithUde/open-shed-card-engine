The real game implementation comes from the local read-only `NiyiOke/open-shed-card-engine` checkout at full commit `f20a5c15bfb2b1aa943f61f8b17bcbd27f185c40`; its package identifies version 1.6.3. The seven selected `lib/game` files were clean relative to that commit. An unrelated untracked `rules-guide 2.ts` was not used. No repository, game rule or existing Site file was edited.

The source repository declares Apache-2.0. Its complete license and attribution are retained in `vendor/LICENSE`; original `types`, `errors`, `random`, `deck`, `invariants`, `engine` and `projection` TypeScript are in `vendor/engine-source/`. The shipped `vendor/engine/*.mjs` are generated with TypeScript 5.9.3 targeting ES2022: type erasure plus `.mjs` suffixes on relative imports, with a modification notice. There are no intentional rule changes. The original and generated byte hashes are recorded in `source-manifest.json`. No proprietary artwork or commercial manual is copied.

Four unchanged teaching modules from the existing `coach-lab/src` supply exact record validation, scripted provider behavior and approved local rule retrieval. The older `runCoach` and approval fixture are **not** used as move executors: they operate on a fixed synthetic permitted-card fixture and issue receipts only. The new `src/lab.mjs` adapter builds temporary `practice-option-N` aliases from the actual engine projection, validates the same structured response and approved `turn` source, and calls `transitionGame` only after a fresh exact human decision.

The game is real code with synthetic seeded input; it is not a mocked move counter. The Coach is a scripted fixture and is explicitly labelled as such. The adapter checks expected revision/reset epoch because the pure engine's transition API alone is not a distributed concurrency service. Local in-memory idempotency, process-local proposals and single-JavaScript-process atomic transitions are not durable or multi-server guarantees.

There is no dependency lockfile because the learner package has no external runtime/test dependencies and needs no install. Exact copied source hashes and the prepared Node 22.14.0 are the relevant runtime pins. Author-only packaging uses an already-installed local ZIP library outside the learner package; learners do not need that library.

Before publishing a new version, rebuild/rehearse the learner allowlist, inspect the exact downloaded bytes and complete a browser/device rehearsal. Never label Node/HTTP evidence as completed browser evidence or a full-course sign-off.
